# FixDrops

Графический интерфейс для выборочного восстановления пропущенных кадров.

**[English version](README.md)**

FixDrops анализирует временные метки кадров — PTS, распределяет исходные изображения по постоянной кадровой сетке и интерполирует пустые позиции.

Поддерживаются OpenCV DIS и внешний `rife-ncnn-vulkan`, кодирование NVIDIA NVENC или CPU.

> **Экспериментальное ПО:** держи независимую копию важных записей. Перед использованием в монтаже проверь ориентацию, синхрон звука и восстановленные участки.

## Возможности

- Номинальные исходные частоты только **24, 30 и 60 FPS**.
- Автоопределение по медианному интервалу кадров.
- Ручной выбор исходного FPS.
- Предварительный статус по метаданным до полного анализа.
- Выборочная интерполяция пустых позиций.
- Опциональная интерполяция конфликтных позиций.
- Половинный выходной FPS без намеренного изменения скорости.
- RIFE или OpenCV DIS.
- Кодирование NVENC или CPU.
- Выход HEVC или H.264.
- Целевой битрейт исходника или ручное значение.
- Применение обычного поворота 90°/180°/270° к изображениям.
- Пакетная обработка и перетаскивание файлов.
- Анализ и восстановление выбранных файлов или всего списка.
- Прогресс с учётом стоимости интерполяции.
- Автосохранение списка, выделения, истории и последнего прогресса.
- Принудительная остановка и остановка после текущего файла.
- Сохранение оригиналов в `original(dropped)`.
- JSON-отчёты с относительными таймкодами `чч:мм:сс:кадр`.

## Какие дропы обнаруживаются

Алгоритм опирается на временные метки.

Он подходит, если пропуски оставили увеличенные интервалы между соседними PTS.

Не гарантируется обнаружение:
- Пропусков, заменённых дублями с равномерными PTS.
- Пропусков, после которых временные метки переписали.
- Отличий между настоящими дропами и похожей на них переменной частотой съёмки.

Пустая позиция выходной сетки не обязательно соответствует физическому дропу камеры.

## Требования

- Основная целевая ОС — Windows.
- Python **3.10 или новее**.
- FFmpeg и FFprobe в `PATH`.
- Зависимости из `requirements.txt`.
- NVIDIA GPU с совместимым драйвером для NVENC либо кодирование CPU.
- Vulkan-совместимый GPU и подходящая сборка RIFE для GPU-интерполяции.

Текущий тракт рассчитан на прогрессивное **SDR-видео, 8 бит**, с квадратными пикселями.

HDR, чересстрочное видео, неквадратные пиксели, произвольные углы поворота и обнаруженные зеркальные display matrix не поддерживаются.

### Использование оборудования

| Операция | Оборудование |
|---|---|
| Анализ PTS и декодирование | CPU |
| OpenCV DIS | CPU |
| RIFE | Внешний `rife-ncnn-vulkan`, обычно GPU/Vulkan |
| NVENC-кодирование | Аппаратный видеокодировщик NVIDIA |
| CPU-кодирование | CPU |

Для этой интеграции RIFE не требуется окружение PyTorch/CUDA.

## Установка

Установи Python-зависимости:

```bash
python -m pip install -r requirements.txt
```

FFmpeg устанавливается отдельно. Проверка:

```bash
ffmpeg -version
ffprobe -version
```

Запуск:

```bash
python fixdrops_gui.py
```

Следующие файлы должны лежать рядом:

```text
fix_drops.py
fixdrops_gui.py
fixdrops_gui_impl.py
fixdrops_worker.py
fixdrops_worker_impl.py
```

Файлы `_impl.py` нужны для работы — это не старые резервные копии.

## Настройка RIFE

Используется сторонний проект:

https://github.com/nihui/rife-ncnn-vulkan

Если его нет в твоём пакете, скачай совместимый Windows-релиз:

https://github.com/nihui/rife-ncnn-vulkan/releases

Распакуй сборку целиком, сохранив сопутствующие файлы и лицензии.

В интерфейсе:

1. Выбери **Engine → RIFE**.
2. В **RIFE executable** укажи `rife-ncnn-vulkan.exe`.
3. В **RIFE model folder** укажи папку совместимой модели RIFE v4.
4. Выбери нужный **GPU ID**.
5. Запусти **Benchmark** на коротком ролике.

Пример путей:

```text
third_party/rife-ncnn-vulkan/rife-ncnn-vulkan.exe
third_party/rife-ncnn-vulkan/rife-v4.6/
```

Папка модели должна содержать настоящие файлы модели.

### Особенности интеграции RIFE

- Для правильных промежуточных моментов требуется поддержка произвольного timestep.
- Каждый синтезированный кадр создаётся отдельным запуском RIFE.
- Опорные PNG повторно используются для одной пары кадров.
- Загрузка модели, запуск процесса и файловый ввод-вывод могут заметно замедлять обработку.
- Полноразмерный кадр может не помещаться в видеопамять.
- Автоматическое разбиение на тайлы и уменьшение разрешения не реализованы.
- При ошибке формата timestep worker пробует десятичную запятую и точку.

Это рабочая интеграция, но не постоянно загруженный в память высокопроизводительный RIFE-процесс.

## Основной порядок работы

1. Добавь файлы или папку либо перетащи их в список.
2. Посмотри предварительные сведения FPS.
3. Выбери движок и исходный FPS.
4. Выполни benchmark выбранных настроек.
5. Нажми анализ или восстановление выбранных файлов либо всего списка.
6. Проверь результат в монтажной программе.

Добавление папки выполняется без рекурсии. `original(dropped)` исключается из обычного импорта папки.

Пути с пробелами поддерживаются.

## Предварительный статус

До полного анализа сравниваются средний FPS из метаданных и ближайший разрешённый номинал либо вручную выбранная частота.

| Расхождение | Статус |
|---|---|
| Ноль с техническим допуском вычислений | `Excellent` |
| Больше нуля, до 0,3% | `Very good` |
| Больше 0,3%, до 2% | `Good` |
| Больше 2%, до 5% | `Fair` |
| Больше 5%, до 10% | `Poor` |
| Больше 10% | `Very poor` |

**Это эвристика, а не подтверждённая оценка качества или отсутствия дропов.**

Например, средние 30 FPS могут означать как нормальный источник 30 FPS, так и сильно повреждённый источник с более высокой частотой. Если номинал известен, выбирай его вручную.

### Разрешённые частоты

Автоанализ выбирает только:

```text
24 / 30 / 60
```

Дробные стандарты не сохраняются как отдельные выходные частоты:

```text
23,976 → 24
29,97  → 30
59,94  → 60
```

Меняется выходная сетка, а не исходные PTS.

Если медианная оценка отличается от ближайшего разрешённого номинала более чем на 5%, программа просит ручной выбор.

## Основные настройки

| Настройка | Назначение |
|---|---|
| Engine | `DIS fast`, `DIS medium` или `RIFE` |
| Source FPS | `auto`, `24`, `30` или `60` |
| Collisions | Ближайшее исходное изображение или интерполяция конфликтной позиции |
| Half FPS | Выходная частота вдвое ниже номинала |
| Encoder | `nvenc` или `cpu` |
| Codec | `hevc` или `h264` |
| Flow width | Размер для оценки движения DIS |
| Bitrate Mbps | Ручной видеобитрейт; пусто — целевой битрейт исходника |
| RIFE executable | Путь к программе RIFE |
| RIFE model folder | Папка модели |
| RIFE GPU ID | Индекс устройства RIFE |

`Flow width` влияет на DIS, но не на RIFE.

Половинная частота:

```text
60 → 30
30 → 15
24 → 12
```

Битрейт — цель VBR. Фактический средний битрейт и размер файла могут отличаться.

## Прогресс и benchmark

Первоначальный benchmark оценивает стоимость:
- Декодирования.
- Преобразования изображений.
- Интерполяции.
- Кодирования.

До анализа прогноз строится по метаданным.

После анализа worker рассчитывает:
- Число выходных кадров.
- Пустые позиции.
- Конфликтные позиции.
- Число запланированных вызовов интерполятора.

Прогресс учитывает отдельно обычную обработку кадров и интерполяцию. Участок с большим количеством RIFE-вызовов имеет больший предполагаемый вес.

### Точность

Процент отображается целым числом, но **это не означает точность прогноза времени ±1%**.

- Скорость зависит от диска, загрузки GPU, запуска модели и движения.
- На склейках и краях возможны повторы вместо синтеза.
- Вызов интерполятора не всегда означает нейросетевой расчёт.
- Прогноз может измениться после анализа и по мере измерения реальной скорости.
- Полоса очереди показывает завершённые файлы и часть текущего, а не точный временной вес всей очереди.

После смены оборудования, драйверов, модели или настроек benchmark можно выполнить заново.

## Работа с оригиналами

Перед восстановлением оригинал перемещается в:

```text
original(dropped)/
```

Результат сначала создаётся временно и проверяется. После успешной обработки он получает исходное имя.

Пример:

```text
Videos/
├── clip.mp4
├── clip.mp4.drops.json
└── original(dropped)/
    └── clip.mp4
```

Верхний `clip.mp4` — исправленный результат.

Существующий резервный оригинал намеренно не перезаписывается. Если одноимённый файл уже лежит в `original(dropped)`, восстановление блокируется.

> Перенос в подпапку — не независимая резервная копия. Для важных записей нужна отдельная копия на другом носителе.

## Остановка

### Stop after current

Завершает текущий файл и отменяет остальную очередь.

### STOP NOW

Запрашивает завершение дерева процессов worker, включая его FFmpeg/RIFE, затем пытается вернуть оригинал, если исходный путь свободен.

В Windows используется `taskkill /T /F`.

Если проверенный результат уже подставлен, он может остаться, а оригинал будет в `original(dropped)`.

Не закрывай программу принудительно во время возврата файла. После аварии или отключения питания проверь:
- Исходное расположение.
- `original(dropped)`.
- Оставшиеся каталоги `.fixdrops_job_*`.

Продолжение с промежуточного кадра не реализовано.

## Список и история

Состояние сохраняется автоматически:
- Примерно каждые две секунды при изменениях.
- После завершения заданий.
- При обычном закрытии.
- При очистке списка.

**Save session нажимать необязательно.** Кнопка только выполняет немедленное сохранение.

Сохраняются:
- Список файлов.
- Выделенные строки.
- Статусы.
- Последний прогресс.
- Размер и время изменения файлов.

### Статусы истории

| Статус | Значение |
|---|---|
| `✓ Fixed` | Программа зарегистрировала успешное восстановление |
| `✓ Zero FPS diff` | Средний FPS совпадает с выбранным номиналом |
| `Analyzed` | Анализ завершён |
| `Stopped` | Остановлено в текущем запуске |
| `Interrupted` | Ранее активное задание не зарегистрировано как завершённое |
| `Error` | Ошибка обработки |
| `File changed` | Изменился размер или время изменения файла |

**`✓ Zero FPS diff` не доказывает отсутствие дропов.**

История привязана к полному пути, размеру и времени изменения. Это не хеш содержимого и не защита от всех возможных подмен файла.

Прерванное восстановление начинается заново. Сохранённый процент — история, а не точка продолжения.

### Clear list

Очищает текущий и сохранённый список, но не удаляет:
- Видео.
- Резервные оригиналы.
- Историю обработки.

При повторном добавлении неизменённого файла его статус может восстановиться.

## Время и звук

Выходные позиции привязаны к исходным PTS.

Начало промежуточного закодированного видеопотока измеряется и компенсируется перед сборкой.

Аудио копируется непосредственно из исходника без намеренного перекодирования, растяжения и обрезки.

Однако:
- Время показа отдельных исходных изображений округляется к CFR-сетке.
- Все выходные изображения проходят преобразование цвета и перекодирование.
- Конец видео округляется вверх до целого кадра.
- Сложные edit list и особенности конкретного редактора не проверяются исчерпывающе.
- Уже существующий дрейф разных камер не исправляется.

Автопроверка контролирует начало выходного видео и доступное число кадров. Это не полная проверка аудиовизуального синхрона.

## Отчёты и таймкоды

Формат относительных таймкодов:

```text
чч:мм:сс:кадр
```

Отсчёт — от первого видеокадра, частота — выбранный исходный номинал.

Это не камерный timecode. Камерные timecode/data-потоки и общие метаданные эта версия не переносит.

Отчёт содержит статистику PTS, подозрительные разрывы, счётчики обработки и результаты проверки времени.

## Проверка аудиосэмплов

Сравнение первой аудиодорожки:

```bash
ffmpeg -v error -i "original(dropped)/clip.mp4" -map 0:a:0 -vn -c:a pcm_s32le -f hash -hash sha256 -
```

```bash
ffmpeg -v error -i clip.mp4 -map 0:a:0 -vn -c:a pcm_s32le -f hash -hash sha256 -
```

Совпадающие хеши означают одинаковую последовательность декодированных сэмплов в этом сравнении.

Хеши не проверяют временное положение звука относительно картинки.

## Устранение проблем

### Не выбран RIFE executable

Выбери сам `rife-ncnn-vulkan.exe`, а не каталог.

### Модель RIFE не загружается

Проверь файлы модели, совместимость и структуру распакованной сборки.

### Не хватает видеопамяти

Проверь короткий исходник меньшего разрешения. Автоматические тайлы RIFE не реализованы.

### Ошибка NVENC

Проверь драйвер NVIDIA и сборку FFmpeg либо выбери CPU.

### Обработка блокируется существующим оригиналом

Сначала проверь `original(dropped)`. Блокировка защищает исходник от перезаписи.

### Проверка времени не пройдена

Не используй результат для ответственной синхронизации, пока причина не выяснена. Сохрани лог и JSON-отчёт.
